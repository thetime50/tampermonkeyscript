# read_copy 站点配置

## 文件结构

| 文件 | 作用 |
|---|---|
| `index.js` | 油猴入口：`@match` / `@require`、组装 `cfgList`、调用 `cfgListExec` |
| `../common/common.js` | 公共工具：`cfgListExec`、`readToCopy`、`delay` 等 |
| `../common/playSite.js` | play-site 接口与页面桥：`getPlaySiteHandle` |
| 站点脚本 `xxx.js` | 各站点逻辑，导出 `getXxxCfg(...)` |

新增站点：写 `getXxxCfg` → 在 `index.js` 加 `@match`、`@require` → 放入 `cfgList`。

本地调试：仓库根目录 `node switch-env.js`，油猴安装 `http://localhost:5500/read_copy/index.js`。

## 匹配与执行（`cfgListExec`）

`cfgList` 项可以是单个配置对象，或配置数组（会先 `concat` 展平）。

按数组顺序找出**所有命中**的配置，依次 `await cb()`。匹配字段三选一，优先顺序：`hostname` → `includes` → `re`。

```ts
type SiteCfg = {
  hostname?: string // href 或 hostname 包含该字符串，如 'xx.com'
  includes?: string // href.includes(...)，如 '//xx.com/a/'
  re?: RegExp       // 正则测 href，如 /^https:\/\/xx\.com\/user\//
  cb: () => void | Promise<void> // 命中后执行
}

type SiteCfgExport = SiteCfg | SiteCfg[]
```

同站点多 URL / 多功能用数组多项；同一页可命中多条并依次执行。

## `getXxxCfg` 模板

用 **函数** 导出配置（不要用 `const xxxCfg = (()=>{})()`）。  
需要 play-site 能力时接收 `getPSHandle`；不需要则无参。

```js
// 不需要插件
function getFooCfg() {
  return {
    includes: '//example.com/path/',
    cb: async () => { /* ... */ },
  }
}

// 需要插件
function getBarCfg(getPSHandle) {
  const playSiteHandle = getPSHandle()
  return [{
    includes: '//example.com/a/',
    cb: async () => { /* 使用 playSiteHandle */ },
  }, {
    re: /^https:\/\/example\.com\/b\//,
    cb: async () => { /* ... */ },
  },{
    hostname: "docs.qq.com",
    cb: () => Promise.all([fun1(), fun2(), fun3()]), // 多个功能，这样将功能抽取为函数应用是比较规范的
  }]
}
```

`index.js` 组装模板：

```js
function getPSHandle() {
  return getPlaySiteHandle({ origin: 'https://example-play-site.com' })
}

const cfgList = [
  ...getFooCfg(),
  ...getBarCfg(getPSHandle),
  {
    hostname: 'example.com',
    cb: () => { /* 内联也可 */ },
  },
]

cfgListExec(cfgList)
```

注意：站点脚本里请用 `function getXxxCfg(){}`，不要用 `const getXxxCfg = () => {}`（`@require` 顺序下函数声明更稳妥）。

## playSiteHandle / ensureBridge

`getPlaySiteHandle({ origin })` 返回 handle（登录态仅内存；请求靠 GM 携带站点 Cookie）。

| API | 说明 |
|---|---|
| `ensureBridge()` | 向页面注入 `window.__site_tool`，供同源页读取 |
| `request(path, options)` | `GM_xmlhttpRequest` 调 play-site；401 时清空内存 `user` |
| `tryLogin()` | 调 `/api/auth/me`；成功写入 `user`；401 清 `user` 并打开登录页 |
| `user` / `loggedIn` | 内存中的用户快照 |
| `clearUser()` | 清空内存用户 |
| `redirectToLogin()` | 新窗口打开登录页 |

桥结构（`ensureBridge` 注入）：

```js
window.__site_tool = {
  name: 'site-tool',
  version: '1.0.0',
  ready: true,
  playSite: {
    loggedIn: false,
    user: null,
    token: null,
    updatedAt: 0,
  },
}
```

注入完成后会派发 `site-tool:ready`。

### 模板：在站点 cfg 里暴露桥 / 调接口

每个站点抽取getXxxCfg()到单独文件

```js
function getPlaySiteCfg(getPSHandle) {
  const playSiteHandle = getPSHandle()
  playSiteHandle.ensureBridge() // 暴露 window.__site_tool
  return [
    // {
    //   includes: '//example-play-site.com/',
    //   cb: () => playSiteHandle.ensureBridge(),
    // }
  ]
}

function getBarCfg(getPSHandle) {
  const playSiteHandle = getPSHandle()
  return [{
    includes: '//example.com/',
    cb: async () => {
      await playSiteHandle.request('/api/...', { method: 'POST', body: {} })
    },
  }]
}
```
